# Project guidance

Keep this file as the maintained project guide.

## Project orientation

Personal, non-commercial proof of concept: warn a film-set sound mixer before an aircraft becomes audible at a set address. See `README.md` for what it does and its data sources.

- Requires Node 22 or newer (uses built-in `fetch` and `node:test`). No dependencies and no build step; there is nothing to install.
- Run: `npm start`, then open `http://127.0.0.1:8787`. It also listens on this machine's Tailscale address when Tailscale is running. `PORT` overrides the port.
- Check: `npm test` (verified). There is no linter or type check.
- `server.js`: serves `public/` and proxies the free flight-data, geocoding, elevation, and runway services. It holds no user state: only short-lived caches, the runway list, and the traffic counters, unless `LOG_DIR` is set (`log.js`, below). `queue.js` is the shared, rate-limited line to each upstream service.
- `access.js`: the access password, on only when `PASSWORD` is set (`PASSWORD=test npm start`). It decides every request before anything is served. Without the cookie only what `login.html` loads, and `public/about.html`, gets out (the `OPEN` list), and `test/access.test.js` checks that list against the files. `login.html` sits beside `server.js`, not in `public/`. The server cannot see the path it is published under, so nothing here may emit an absolute URL or a cookie `Path`.
- `public/feed.js`: reads flight responses without leaking proxy HTML/JSON parser errors, and parses Retry-After for both proxy and browser. The server pauses a flight provider for all locations (including queued work) on its 429, in every mode, respects provider delays and increases repeated backoff; each provider has its own pause (adsb.lol's saved with its budget), so in private mode adsb.fi is asked while adsb.lol waits, and with every provider waiting the server answers itself; the browser also pauses polling, showing the server's countdown but asking again within a minute (`pacer()` and `wait()`, which `poll()` in `app.js` uses and `test/feed.test.js` checks), since the server answers a paused request without calling the provider. Failed/stale responses never become empty successful feeds. A coordinate change clears previous predictions and emits dataAt:0 until a new feed arrives; in-flight polls for older site objects must not update state. The map treats dataAt:0 as no data for this location.
- `consent.js`: ephemeral server-issued sharing grants. `POST /api/sharing` starts consent and `DELETE /api/sharing` revokes it (even when the API quota is exhausted). Uploads and final feed/search recording must recheck that same grant after awaits. The browser preference is `hfs:share:v3`; older consent does not bypass the problem-report confirmation. Accept and share is required before a grant request; Decline and Escape leave sharing off. A grant lasts an hour, renewed by each use up to a day. One client network (`network()` in `stats.js`) holds at most 6 live grants and starts at most 12 a day. A reloaded or duplicated tab presents its grant (sessionStorage) and is given a new grant and session, not charged to the 12 but to its own 48 a day; the old grant ends by its own `?closing` (a minute later) or expiry. Exchange and `?closing` act only for the grant's own network. Behind `PASSWORD`, every sharing method needs the cookie.
- `activity.js`: opt-in-only, bounded approximate region and rounded search aggregates, held in memory for about 24 h (100 groups per view); never raw queries, address names or audio. In public mode `OWNER_PORT` exposes the stats plus this activity on loopback only. A proxy such as Cloudflare supplies the location headers; the sharing switch's consent text discloses this optional aggregate collection. No optional activity is collected without a live grant.
- `stats.js`: the traffic counters and `GET /api/stats`, which answers only a request made on the machine itself. Other tools may read that JSON, so keep its shape. `client()` and `direct()` there say who is asking. To imitate a forwarding proxy with `curl`, send `x-forwarded-for` and `x-forwarded-proto: https` yourself.
- `receiver.js`: merges an ADS-B receiver's `aircraft.json` (`RECEIVER`, off by default) into the feed. It has only ever run against a stand-in; nobody has the hardware yet.
- `log.js`: the opt-in session log, on only when `LOG_DIR` is set (`LOG_DIR=logs npm start`). `GET /api/log` says whether sharing is offered and `POST /api/log` stores a consent-authorized batch; neither is counted as `api` in `stats.js`. A session is up to three gzip files named from its day and id: the page's records, the feed it was served (in the `REPLAY` format; `read()` there is also the `REPLAY` loader), and the spectrogram. `node log.js <LOG_DIR>` prints a line about each session, and `spectrogram()` reads a stretch back into dB. Session files are deleted 90 days after the day they began (at start and daily). Covered by `test/log.test.js`.
- `contact.js`: the **Contact me** form's server side (`POST api/contact`, urlencoded, at most 16 KB): `check()` validates the fields (a filled `website` honeypot is refused), `limits()` allows 3 messages per client network per 15 minutes (in memory) and 30 a day in all (the send times only, saved as `contact.json` in `STATE_DIR` or `LOG_DIR` like `adsb-lol.json`: a failed save refuses the send, an unreadable file is a spent day), and `webhook()` delivers by POSTing JSON to `CONTACT_URL` (with `CONTACT_TOKEN` as a bearer token), following no redirect: only a 2xx is sent. `dispatch()` sends one at a time through the `contactLine` queue in `server.js`, each answered within `TOTAL_MS` of its arrival, 5 s inside the page's `WAIT_MS` (`public/contact-core.js`, which also has the page's wording); one whose page has gone or whose time is up before its turn is dropped unsent. No answer from delivery in time, or none reaching the page, is **Delivery unconfirmed**, never "Not sent". Without `CONTACT_URL`, `GET api/contact` says `{ on: false, sitekey: null }` and `public/contact-form.js` puts nothing on the page. With `CONTACT_SITEKEY` (a Cloudflare Turnstile site key), `GET api/contact` gives it as `sitekey`, the page loads Turnstile only when the dialog first opens (never on load), renders it with action `contact` and sends its token as `cf-turnstile-response` (required then, refused without a site key, at most 2,048 characters), and the relay adds `token` and `ip` (the address the limits count, before IPv6 /64 grouping) for the receiver to verify; a 400 from delivery is "Complete the check and try again." The public CSP adds `https://challenges.cloudflare.com` to `script-src` and `frame-src` only then. Nothing of a message is logged or kept. Covered by `test/contact.test.js`.
- `public/share.js`: the **Share data with the developer** switch at the bottom of the page and the two marks, **I hear an aircraft** and **Quiet now**. None of it is on the page unless the server keeps a log. It tells `app.js` the session's id with `hfs:share`, so the feed request names it. What is recorded and sent, the 30 s of spectrogram remembered, and the batches, are in `public/share-core.js`, with no page in it, covered by `test/share.test.js`. `listen-core.js` hands over each second of listening through `report()`, which `listen.js` sends as `hfs:heard`. `public/share.css` puts the marks where nothing else is (the top line on a tablet, a strip along the bottom on a phone), so showing them moves nothing: keep it that way.
- `public/predict.js`: path prediction and received loudness, as pure functions shared by the browser and the tests. Each aircraft gets one path: takeoff (on a runway), landing (on final), or straight line. Change predictions here and cover them in `test/predict.test.js`. `windEnds()` narrows taxi guesses on an unobserved runway using fresh 10 m wind (at least 3 m/s, with a 2 m/s headwind component); observed use and aircraft already lined up or rolling win. Crosswinds leave both ends, and the unseen-departure advisory still covers both directions. The level is `source.js` plus `weather.js` less `propagate.js`, the building and `ANCHOR_DB` (3 dB, which keeps the recorded reference pass, a jet landing about 380 m away, near the level the earlier single-formula model gave it). Environment keys are `outdoors`, `indoors`, `warehouse` (converted/lightweight stage), and `stage` (purpose-built); preserve these saved keys. `shortcut:` loss/floor guesses are 0/45, 25/35, 25/30, and 45/25 respectively, with helicopters using 80% of the loss; replace with measured in-room levels. See README.md for the basis.
- `public/source.js`: pure source level at 1000 ft, with conservative type offsets, engine/size fallbacks, point velocity and phase, jet aft and propeller broadside lobes, and helicopter descent noise. EASA certification differences are rough relative proxies, never a conversion from EPNdB to dBA. Category `trim` stays additive. Tables and thresholds are uncalibrated guesses; covered by `test/source.test.js`. Path positions in `predict.js` stay unchanged.
- `public/propagate.js`: pure spherical spreading, ISO 9613-1 air absorption beyond the 305 m reference, and AIR5662 lateral attenuation with the ECAC engine-installation correction. Representative spectra and instantaneous geometry are uncalibrated approximations (`shortcut:`); unknown engines use the less attenuating propeller curve, unknown mounts use the loudest correction, and lateral shielding is capped at an uncalibrated 3 dB and never exceeds the previous horizon allowance. `elevation()` returns degrees; the sample’s horizontal distance supplies the short-segment lateral distance (Doc 29 4.5.5) for other propagation terms. Covered by `test/propagate.test.js`.
- `weather.js`: background hourly Open-Meteo forecast cache (failures included; a place is forgotten an hour after its fetch, swept every minute), rounded to 3 decimals, queued through `server.js` and counted as upstream; returned with live `/api/aircraft`, absent for replay. No new client request or sharing fields. `public/weather.js` supplies pure stability and low-angle refraction; quietening capped at 3 dB with weather at most an hour old and excluded below 100 m within 3 km. Inversion gain up to 5 dB, no extra downwind wind gain over lateral attenuation. All thresholds are `shortcut:` guesses; covered by `test/weather.test.js`.
- `public/motion.js`: each aircraft's last 90 s of reports, kept by `app.js`, and what they say about how it has been moving (how much it turns, whether it is hovering or circling). It also keeps reports on the ground, for `gaining` (the newest speed faster than the one before, a speed repeated with no new position included) and `way` (which way it has moved over the last 10 s, to check a ground heading against). `predict.js` uses it for helicopters, and for an aircraft starting its takeoff roll. Pure, covered by `test/motion.test.js`.
- `public/about.html`: the plain page of notices (About, Privacy, Credits), linked from the footer and the sharing text. No scripts. `public/changes.html` is the patch notes, newest first, also plain and linked from the footer's version button. The version is `version` in `package.json` (major.minor shown as `v1.1`): when a change is worth a note, raise it there, in the footer button in `index.html`, and with a new entry at the top of `changes.html`; `test/version.test.js` checks they agree. The footer is one line of text, a row of links (About and privacy, Source) and the two small buttons (Contact me, added by `contact-form.js`, and the version), which wrap together, and the credits. Its Privacy section must stay true to what the server and page do, and to the consent line.
- Public-mode abuse limits in `server.js`: per client address, 5 distinct places and 10 lookups per 10 minutes, 3 sharing grants, and 24 MB of posts per grant and 48 MB per address an hour; one flight answer per rounded place for 10 s while anything may matter soon, and while the sky is quiet 30 s within 5 km of a runway or 60 s elsewhere (`cadence.js`, decided by the server from the last answer, never by the page), a 1.6 s gap between flight requests, and a server-wide adsb.lol budget (`ADSB_LOL_DAY`, default 900 a rolling day; `ADSB_LOL_WEEK`, default 4500 per 7 days; `ADSB_LOL_MONTH`, default 9000 per 30 days; a free key allows 1,000 a day, 5,000 a week and 10,000 a month) that pauses with the quota message. Its request times are saved in `STATE_DIR` (or `LOG_DIR`) as `adsb-lol.json`: a request whose time cannot be saved is not made (503), and a file that cannot be read or understood counts as a day spent from start-up; a missing one is a fresh start. Covered by `test/public-server.test.js`.
- The page may be served under a path, so keep every URL in `public/` relative (no leading slash).
- Public static assets use `no-store`; this avoids Cloudflare converting `no-cache` to a long browser cache lifetime. The page loads every script and stylesheet under `r/<release>/` (`r/RELEASE/` in `index.html`, filled in by `server.js` with a hash of `public/` and stripped when serving), so each release is a new address for every file and no browser can run a copy cached from an earlier one; there are no version numbers to bump. `public/boot.js` imports nothing and runs first: if `app.js` has not started (`data-started` on `<html>`) 6 s after load, the banner says Didn't load with the browser's error.
- Setup uses the native `#settings` dialog, opened by `#change` and on a fresh start. It never pushes the dashboard down, and reopening resets its scroll after showModal. Watch, lookup feedback and presets stay together in the location column. `page.css` gives it two columns on desktop/tablet and one scrollable column on a phone, with a sticky Close heading. UI text uses the system font; instrument readouts keep Barlow.
- `public/app.js`: polling, the status banner, and in-app notifications. It also remembers which aircraft were recently on final approach and which runway directions are in use. Settings live in the browser's `localStorage`.
- The page's parts are separate modules joined by events on `document`; none imports `app.js`. `app.js` sends `hfs:update` after every poll, with the feed, every aircraft's predicted path (`tracks`), and the audible `windows`, and `hfs:status` when the banner changes. Any module sends `hfs:select` to highlight one aircraft everywhere, and `listen.js` sends `hfs:tune` with what the microphone has learned. `listen.js` also sends `hfs:timing`, how early or late fitted curves say the feed has been, which `app.js` uses to widen audible windows (never narrow them) through `public/widen.js`: pure, covered by `test/widen.test.js`. It leaves estimated (`lost`) windows alone and keeps a widened window until its widened end after the prediction drops it, so the banner never goes Clear before an end it announced. Only a curve that fits exactly one aircraft is that aircraft's, and none heard while the data was stale or that aircraft's track an estimate gives an offset. The comment at the top of `app.js` is the reference for these events. `public/map.js` and `public/listen.js` each draw inside their own `<section>` and have their own stylesheet.
- `public/map.js`: the map. Its geometry is in `public/map-geo.js`, covered by `test/map.test.js`. `#map` must stay a positioned element. The zoom step is kept in `localStorage` under `hfs-map`. The wind button uses `hfs:update.weather` from app.js, never its own fetch or freshness check; mph/knots is saved separately under `hfs-map-unit`. Pure formatting and downwind geometry live in `map-wind.js`, covered by `test/map-wind.test.js`; `freshWeather()` in `public/weather.js` is shared with prediction.
- `public/listen.js`: the timeline panel. It captures the microphone through `public/listen-worklet.js` and draws the spectrogram and forecast. What the panel knows and decides (the engine, what is stored, when to send `hfs:tune`) is in `public/listen-core.js`, with no page in it, covered by `test/listen-core.test.js`, which plays `app.js`'s side of the tuning exchange: keep that stand-in in step with `app.js`. Timeline geometry, the audio clock and all wording are in `public/listen-view.js`, covered by `test/listen.test.js`. Observations are kept in `localStorage` under `hfs:listen`, one list per set and environment. Each pass keeps the level predicted for it, so the stored text carries the loudness scale (`SCALE` in `listen-view.js`): raise it whenever the loudness model changes, and passes from an older scale are dropped (the input chosen is kept). Nothing from the demo source is stored, and everything it sends carries `demo: true`.
- Tuning has one rule: on every update `listen-core.js` compares what it has learned for this set and environment with the `learned` and `trim` the page reports, and sends `hfs:tune` when they differ. `app.js` drops its tuning when the set or environment changes. Unheard aircraft never raise the learned level.
- `public/theme.css`: the shared colour names and type scale, light and dark. Stylesheets and canvases use these names and never their own colour values. `public/page.css` is the page's layout and components, and sizes the boxes of the map and the listening panel. The tablet is the screen it is designed for: its "first screen" section fits the status, map, aircraft list and timeline chart on one screen with every box sized from the screen, and smaller windows get the scrolling phone layout. It sets four properties on `#listen` (`--fold`, `--chart`, `--below`, `--heading`) that `listen.css` reads. `#bar` is the slim status bar shown while the banner is scrolled away; `show()` in `app.js` sets banner and bar together, so they cannot disagree. `public/fonts/` holds the typeface (Barlow Semi Condensed) and its licence.
- Setup’s **Try a live location** buttons use fixed public coordinates for Dockweiler Beach (LAX), Gravelly Point (DCA) and Bayfront Park (SFO). They fill the field and submit through the same watch path, without enabling sharing or device location. The latest submitted lookup owns the result; older completions cannot overwrite it.
- `public/crew.js`: pure crew-fragment validation, link generation and saved-set comparison, covered by `test/crew.test.js`. Setup shares only coordinates (at most 4 decimals, preserving the server's 3-decimal place), environment and slider level; all query parameters are removed. `app.js` confirms a different saved set, submits through Watch, and applies the linked level as a manual setting against local learning. Login and slash redirects preserve the fragment.
- `public/locate.js`: what the **Use my location** button (`#here`, under the address field) decides. A reading from the browser becomes coordinates for the field (4 decimals), or the place already being watched when it is within 50 m or twice its own accuracy of it, or a refusal when it claims no better than 100 m; and it has the words for every way there is no reading. Pure, covered by `test/locate.test.js`. `app.js` asks the browser once for each press, and `watch()` there looks the field up for both buttons. The server reads the coordinates as typed ones, so they never reach the address lookup.
- `public/unheard.js`: pure, per-window quiet-microphone evidence for helicopters, covered by `test/unheard.test.js`. After 20 continuous ready seconds during an audible window it permits Heads up / not heard; any rise or engine detection restores the hold for the rest of that window. `listen-core.js` sends ephemeral `hfs:audibility` (at, hexes); `app.js` expires it after 2 s and applies it only to reported current helicopters through `status.js`. Stop, mute, background reset, set/environment change, demo and stale data clear evidence. No tuning, storage or sharing fields change.
- `public/status.js`: what the status banner says, worked out from the audible windows. Pure, covered by `test/status.test.js`. Flight data is trusted for 20 s, or a third longer than the server says it keeps the answer (80 s for a minute, 40 s for 30 s: `every` in `/api/aircraft`, `staleAfter()`); `app.js` passes that on as `staleMs` in `hfs:update`, and `map.js`, `listen-core.js` and `lost.js` use it, never a 20 s of their own.
- `cadence.js`: in public mode, how long the server keeps a place's flight answer: 10 s while an aircraft could come within about 10 km before a quiet answer runs out or within 15 minutes on its heading, or one on the ground nearby is moving or new (and 10 minutes after), else 60 s, or 30 s (trusted 40 s) within 5 km of a runway or while the server's runway table has not loaded. Expired answers are swept a minute after they run out (10 minutes where aircraft were on the ground nearby). Thresholds are uncalibrated guesses. Pure, covered by `test/cadence.test.js`; arithmetic in `README.md` (Optional official free flight key).
- `public/engine.js`: jet, turboprop, piston, propeller or helicopter, from a feed row's type designator (a small table) and then its category; the icon in each list row shows it. `public/details.js`: the labels and values of an opened row, from the window and the feed's row, leaving out what the feed did not send. Both pure, covered by `test/engine.test.js` and `test/details.test.js`.
- `public/lost.js`: which aircraft are predicted on each poll, including ones the feed has lost. Their last position is carried forward as an estimate (`lost: true` and `seenAt` on tracks and windows) for up to 2 minutes; `lost` means the newest answer leaves the aircraft out or has a position 20 s older than the answer itself, never anything to do with how long the server keeps answers; a window still open when that runs out is kept as `unsure` with no track, which the banner shows as "cannot tell", never as a hold or as clear. An aircraft lost while lined up on a runway is `unsure` at once, until it is seen again or its position is 2 minutes old. Pure, covered by `test/lost.test.js`.
- `public/hear.js`: the listening engine. Microphone audio and predicted tracks in; a spectrogram, what is being heard and from which aircraft, and observations of each pass out. Pure, with no DOM or clock; its API is the comment at the top of the file. It also fits the tones whose pitch bent as straight flybys (`curves` in its status) with `public/doppler.js`, which is pure and covered by `test/doppler.test.js` with an invented fixture, `test/fixtures/curve.json`. `public/tune.js` turns stored observations into the `hfs:tune` settings. `public/synth.js` makes the sound a microphone would pick up for given tracks, for the tests and the demo. Every threshold in these is an uncalibrated guess, like the numbers in `predict.js`.
- To work on the page without the live feeds, run `REPLAY=test/fixtures/lax.jsonl PORT=8790 npm start` and enter `33.938, -118.440`. It replays six and a half minutes of adsb.lol traffic beside LAX on a loop (early morning, over-ocean flow: a departure overhead and heavy jets landing on 6R). Choose Indoors to see heads-ups, holds and clears. The timeline's demo sound exercises the listening engine without a microphone.
- To see sharing at work, add `LOG_DIR=<a folder>` to that command, switch it on at the bottom of the page, and read what it wrote with `node log.js <the folder>`.
- To look at the page from a script, drive headless Chrome over the DevTools protocol. Playing a WAV as the microphone needs `--use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<wav> --disable-features=AudioServiceSandbox`; Chrome's default test tone reads as "no signal". A page that the script leaves alone stopped polling after about ten seconds in one run (150 s with no DevTools call); asking it something every few seconds kept it going.

## Working agreements

- Notes that belong to one deployment (hosting, credentials' locations, analysis of shared sessions, plans) are kept outside this repository. When an `ops/` folder is present (git-ignored), read `ops/AGENTS.md` before starting; never commit anything from it here.
- Commits carry no co-author lines. Keep comments, tests and docs free of people, machines, hosts and reviews.

- The page's words are labels and values. Add a description only where what something does is not otherwise obvious; no paragraphs explaining how the page works, reassurance, or helper text under controls. Explanation belongs in `README.md`.

- Follow the user's task and preserve unrelated work.
- Inspect existing architecture and conventions before changing them.
- Keep it small: this is a concept test. Prefer the standard library and the platform over new dependencies, and mark known limits with a `shortcut:` comment.
- Verify the changed behavior with checks appropriate to the task. Distinguish checks that passed from untested behavior.
- Store durable project decisions here or in linked project documentation.

## Boundaries

- Free data only: no paid flight APIs. A free adsb.lol key may be set (`ADSB_LOL_KEY`); keep it server-side, outside the repository. No other keyed or paid services. The services in use are free community services, some with non-commercial terms (see `README.md`). Each watched address may cost one upstream request per 4 seconds at most, all upstream calls go through the queues in `server.js`, and requests send a generic `user-agent`.
- The only requests a viewer's browser makes to a third party are the map tiles, and Cloudflare Turnstile, loaded only when the contact form is opened (and only with `CONTACT_SITEKEY` set). Everything else is served from this repo: no fonts, scripts, or analytics from elsewhere.
- Microphone audio is analysed in the browser. The audio itself is never stored and never sent, by anything, to anyone. Keep it that way.
- Nothing about a session is sent to this page's server or kept there unless its user has switched on **Share data with the developer** (off by default, and absent unless `LOG_DIR` is set). Then the page sends what `public/share-core.js` lists and nothing else: the set's coordinates (never the typed address or the place's name), what the page predicted, the marks, the engine's once-a-second levels and a 38-band spectrum averaged over each second, its record of each pass, and its full spectrogram (304 bins, 8 columns a second, a byte a bin) from 30 s before to 30 s after each predicted aircraft, and to a minute after each mark, and from 10 s before to 10 s after other aircraft-like noise lasting 20 s or more, up to 15 min an hour, never from before the switch went on. The spectrogram stops, and the rest goes on, an eighth short of the session's size (`log.js`). That spectrogram is not a recording and cannot be played back, but it is not private either: loud sounds near the microphone, speech included, show in it. Never describe it as unable to carry speech, never send anything finer (no audio, no phase, no shorter columns), and never send any of it from the demo sound. The line under the switch is the user's consent: whatever is added to what is sent must be said there first. The same switch gates optional connection regions and rounded search-result aggregates (`consent.js`, `activity.js`); these are never collected while sharing is off. Basic numeric traffic and abuse counters remain available.
- The session log never holds a visitor's address, and nothing a client sends may name a file or fill the disk: keep the id pattern, the post limit and the size caps in `log.js`.
- The microphone starts only on a press of its button; nothing resumes listening on load.
- Nothing asks where the device is except a press of **Use my location**, once for each press: no watching the position, and no asking on load. No outside service is sent a set's coordinates finer than 3 decimals (about 100 m).
- The page must never look clear on data it cannot trust: stale data, a hold that has only just ended, and the map and timeline all follow the banner's status rather than working out their own.
- No password in the repository. With `PASSWORD` set, nothing but the login page's own files is served without the cookie, `/api/*` included. The log never holds a visitor's address.
- The server itself listens on localhost and the tailnet address only, never the LAN. A public instance (`PUBLIC_HOST`) listens on loopback only, behind a proxy. Do not remove the queues or input limits while a public link may exist.
- The loudness numbers in `public/predict.js` are uncalibrated guesses. Do not present them as measured.
- Skills and historical notes do not grant permission for external actions.
